mkvis3d / OpenBiomech — Target Architecture (Rust)

Status: this document is the long-term target architecture — a full Rust workspace that has not been started. The project is currently in the Python prototype phase; see CLAUDE.md for what actually exists today and the documentation hub. Nothing here should be read as "already implemented."

OpenBiomech (mkvis3d) targets an ultra-high-performance, cross-platform (Linux, macOS Apple Silicon/Intel, Windows) biomechanical analysis engine and 3D visualization suite: an open-source, reproducible alternative to C-Motion Visual3D and BTK Mokka.

The system decouples into four modular layers:

  1. Core data structures & binary I/O engine — a high-throughput, near-zero-copy parser/writer for standard biomechanical formats (.c3d, .csv, .trc, .mot, .anc).
  2. Computational biomechanics engine — numerically stable linear algebra, dual-pass filtering, rigid-body 6DoF tracking, ISB Joint Coordinate Systems (JCS), recursive Newton-Euler inverse dynamics, anthropometric segment modeling.
  3. Hardware-accelerated 3D viewport & UI — cross-platform rendering via wgpu (Metal / Vulkan / DX12) paired with an immediate-mode UI (egui or Qt6/cxx-qt) and a synchronized high-fps 2D telemetry plot view.
  4. Automation, scripting & IPC pipeline — Python bindings via PyO3/maturin, for batch CLI processing comparable to Visual3D pipeline scripts (.v3s) and interoperability with NumPy/SciPy/Polars.

2. Mathematical & biomechanical standards

Implementations must adhere to International Society of Biomechanics (ISB) conventions and the formal analytical formulations below. This section is the canonical reference for what is correct, independent of the implementation language (Python today, Rust at the target architecture).

2.1 Coordinate system & triad conventions

  • Right-handed orthogonal system: ex × ey = ez, all unit vectors normalized.
  • ISB axis assignment: Z = longitudinal/superior (proximal), X = anteroposterior (anterior, joint-dependent), Y = mediolateral.
  • Unit quaternions (scalar-first, [w, x, y, z], unit norm) hold orientation; Cardan/Euler extraction happens only as a final step, to avoid gimbal lock during intermediate tracking.

2.2 6DoF rigid-body optimal registration (Kabsch-Umeyama SVD)

For each frame, align technical cluster markers (local) to measured trajectories (global):

  1. Compute centroids of local and global marker sets.
  2. Build the centered cross-covariance matrix H between them.
  3. Decompose H = U Σ VT (SVD).
  4. Rotation R = V·d·UT, where d = diag(1, 1, det(VUT)) rejects reflections (det(R) = +1).
  5. Translation p = cy − R·cx.

2.3 Joint Coordinate System (JCS) kinematics

Grood & Suntay / ISB floating-axis parameterization: a proximal (flexion) axis e1, a distal (rotation) axis f3, and a floating axis e_float = (e1 × f3) / ‖e1 × f3‖ perpendicular to both. Joint angular velocity decomposes as ω = α̇·e_flex + β̇·e_float + γ̇·e_rot.

2.4 Signal processing & numerical differentiation

  • Butterworth dual-pass filter — 4th-order low-pass, zero-phase-lag (forward-backward), with the standard cutoff correction for repeated passes.
  • GCVSPL smoothing splines — cubic or quintic splines for smooth velocity/acceleration without amplifying digitizing noise. The Python prototype uses scipy.interpolate.make_smoothing_spline (cubic GCV only — see CLAUDE.md).

2.5 Force plate mechanics & Center of Pressure (COP)

Platform types 1-5. For a type-2 platform with a 6×6 calibration matrix C:

  1. Raw channel forces/moments: F_raw = C · V_analog.
  2. Correct moments for sensor origin offset (x₀, y₀, z₀): Mx' = Mx + Fy·z₀ − Fz·y₀, My' = My − Fx·z₀ + Fz·x₀.
  3. COP in plate coordinates: x_cop = −My'/Fz, y_cop = Mx'/Fz, z_cop = 0.
  4. Vertical GRF threshold: if Fz < F_threshold (default 15.0 N), zero out COP, F, and M to remove non-contact singularities.
  5. Transform COP/reaction forces from plate-local to global lab coordinates using the 4 corner calibration parameters (CORNERS).

2.6 3D inverse dynamics (recursive Newton-Euler)

Executed recursively, distal to proximal, per segment:

  1. Linear momentum balance: F_proximal = m·(a_com − g) − F_distal, with g = [0, 0, −9.80665] m/s².
  2. Angular momentum balance: M_proximal = I·ω̇ + ω × (I·ω) − M_distal − (r_distal × F_distal) − (r_proximal × F_proximal), where I = R · I_local · RT is the instantaneous global inertia tensor.
  3. Joint power: P_joint = M_joint · (ω_distal − ω_proximal).

3. C3D file format specification & parsing rules

Raw 512-byte blocks. The parser must guarantee near-zero-copy performance where feasible and handle historical format anomalies.

3.1 Header block (block 1)

FieldMeaning
Byte 1Pointer to first parameter block (typically 2)
Byte 2Magic key 0x50 (80)
Word 2 (bytes 3-4)Number of 3D points per frame
Word 3 (bytes 5-6)Total analog measurements per 3D frame
Word 4 (bytes 7-8)1-based index of first frame
Word 5 (bytes 9-10)1-based index of last frame
Word 6 (bytes 11-12)Maximum interpolation gap
Words 7-8 (bytes 13-16)3D scale factor: negative → 32-bit float storage; positive → 16-bit int, scaled by |scale|
Word 9 (bytes 17-18)Pointer to first 512-byte data block
Word 10 (bytes 19-20)Analog samples per video frame
Words 11-12 (bytes 21-24)Frame rate (Hz, float)

3.2 Processor architecture flags

Found at byte 4 of the first parameter block:

  • 84 (0x54): Intel little-endian (IEEE-754 float)
  • 85 (0x55): DEC VAX (F-Float/D-Float, swapped 16-bit words)
  • 86 (0x56): MIPS/Sun big-endian (IEEE-754, byte-swapped)
pub fn vax_to_ieee_f32(vax_bits: u32) -> f32 {
    let word0 = (vax_bits & 0xFFFF) as u16;
    let word1 = ((vax_bits >> 16) & 0xFFFF) as u16;
    if word0 == 0 { return 0.0; }
    let sign = (word0 >> 15) & 0x01;
    let exponent = (word0 >> 7) & 0xFF;
    let fraction = (((word0 & 0x7F) as u32) << 16) | (word1 as u32);
    if exponent == 0 && sign == 0 { return 0.0; }
    let ieee_exp = (exponent as i32) - 128 + 127 - 1;
    let ieee_bits = ((sign as u32) << 31) | ((ieee_exp as u32) << 23) | fraction;
    f32::from_bits(ieee_bits)
}

The current Python prototype implements the equivalent decode in openbiomech/c3d_io/legacy_binary.py using NumPy.

3.3 Data storage layout (target Rust)

Struct-of-Arrays (SoA) for contiguous SIMD vectorization: markers as parallel x/y/z/residual/camera_mask arrays, analog as a flattened [Frame][Subsample][Channel] buffer. The Python prototype uses the equivalent NumPy SoA layout.

4. Rust code style & engineering guidelines (target)

These rules apply once the Rust workspace starts. They do not apply to the current Python prototype — see CLAUDE.md § Conventions for the Python rules in force today.

  • Zero unchecked panics — no unwrap()/expect()/bare slicing in library crates; propagate a typed thiserror enum.
  • Precision discipline — f64 for kinematics/SVD/integration; downcast to f32 only for wgpu vertex buffers.
  • Allocation rules — zero heap allocations inside per-frame loops; pre-allocate with Vec::with_capacity or arena/scratch memory.

Testing & parity: every math function gets a ground-truth unit test; synthetic sinusoidal rigid-body motion validates velocity/acceleration/torque; cross-engine tolerance vs. Visual3D: angles ≤ 10⁻⁴°, moments ≤ 10⁻³ N·m, COP ≤ 10⁻² mm.

5. Automation pipeline & Python interoperability (target)

To fully replace Visual3D pipeline scripts (.v3s), the target engine exposes high-level declarative commands via Python:

import openbiomech as ob

trial = ob.load_c3d("subject01_walk.c3d")
trial.filter_markers(cutoff_hz=6.0, order=4)
trial.filter_analog(cutoff_hz=20.0, order=4)

model = ob.BiomechanicalModel.from_static(
    static_c3d="subject01_static.c3d",
    template="isb_lower_limb.yaml",
)
results = model.process_dynamic_trial(trial, kinematic_standard="ISB", bsp_model="Dumas2007")
events = results.detect_gait_events(method="ForcePlateThreshold", threshold_n=15.0)
results.export_csv("kinematics_kinetics_output.csv")

The equivalent already works today with the real openbiomech Python package — see the CLI reference and the README status table.
