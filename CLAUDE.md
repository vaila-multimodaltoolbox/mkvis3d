# CLAUDE.md — OpenBiomech (mkvis3d)

Guidance for AI assistants working in this repository.

## Provenance

`README.md` in this repo was generated by another AI as the **long-term target
architecture**: a full Rust workspace (7 crates: `c3d-io`, `biomech-math`,
`biomech-model`, `inverse-dynamics`, `viewer-core`, `gui-app`, `pipeline-cli`)
plus `wgpu` rendering and PyO3/maturin Python bindings, aiming to replace
C-Motion Visual3D and BTK Mokka. Its mathematical/biomechanical content (ISB
joint conventions, Kabsch-Umeyama registration, Butterworth/GCVSPL filtering,
force-plate COP, recursive Newton-Euler inverse dynamics, C3D binary layout)
remains the canonical reference for **what is correct**, independent of
implementation language.

**This file (`CLAUDE.md`) is the authoritative source for what phase the
project is actually in.** Do not create `Cargo.toml` or `crates/` yet — the
Rust workspace has not started.

## Reference sources

`vendor/` is gitignored scratch space for read-only reference checkouts. The
C3D parser was reverse-engineered against
[BTKCore](https://github.com/Biomechanical-ToolKit/BTKCore)
(`git clone --depth 1 ... vendor/BTKCore`; `Code/IO/btkC3DFileIO.{h,cpp}`).
Where BTK and `ezc3d` disagree — the residual/camera-mask byte roles, and the
sign of `ANALOG:OFFSET` — `ezc3d` wins as the declared oracle, and each choice
is pinned by a named test in `tests/test_c3d_io_native.py`.

## Data

`data/` holds one real vailá `rec3d` export in four parallel formats (same
trial): `.csv`/`.3d` (wide per-marker CSV, identical to each other), `.bvh`,
and `_m.c3d` (binary C3D, 70 markers `p1..p70`, 631 frames, 100 Hz, no analog
channels). This is the golden fixture used to cross-validate the C3D reader
against the CSV — see `tests/test_c3d_io_golden.py`. Do not modify these
files; do not add large binary fixtures without checking size.

## Conventions

- Python 3.12, `uv`/`ruff`/`ty` toolchain (same as vailá — never bare `pip`,
  `black`, `flake8`, `mypy`).
- Scientific variable names (`R`, `T`, `x`, `y`, `z`) are valid; ruff `N806`/
  `N803` are suppressed project-wide.
- `f64`-equivalent precision: use `np.float64` throughout the math modules;
  never silently downcast to `float32`.
- Quaternions are **scalar-first** `(w, x, y, z)` everywhere, per README.md
  §3.1. scipy is scalar-last, so every boundary with it reorders explicitly.
  (vailá's `rotation.py:rotmat2quat` claims scalar-first but returns
  scipy's scalar-last order — do not copy that function.)
- Prefer scipy over re-deriving numerics: `Rotation`/`Slerp` own the rotation
  conversions and `make_smoothing_spline` implements the GCV criterion
  README.md §3.4 calls GCVSPL (cubic only; Woltring's quintic option and its
  reported GCV score are not available through it).
- Every new module in `biomech_math`/`c3d_io`/`model`/`inverse_dynamics` gets
  a deterministic unit test (synthetic ground truth, or the golden fixture)
  before being considered done — see the verification ladder in
  `.claude/skills/preto-loop/references/loop-engineering.md`.
